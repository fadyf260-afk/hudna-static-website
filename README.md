# موقع هُدنة

## لوحة الإدارة أونلاين

بعد إتمام الإعداد أدناه، افتح `https://hudnaapp.com/admin/` وسجّل الدخول بحساب GitHub `fadyf260-afk`. الحفظ يُحدّث ملفات المحتوى على فرع `main` مباشرةً، ثم يبني GitHub Actions الصفحات والمقالات وsitemap وRSS وينشرها على GitHub Pages. ظهور التغيير يستغرق عادةً بضع دقائق. يمكن الاستمرار في التحرير المحلي من VS Code أيضًا.

### الإعداد لمرة واحدة

1. ادمج هذا الفرع في `main` بعد مراجعة التغييرات. في **Settings → Pages → Build and deployment → Source** اختر **GitHub Actions**. الـworkflow في `.github/workflows/deploy-pages.yml` ينشر `.site-dist` ويحافظ على الدومين الموجود في `CNAME`.
2. أنشئ **GitHub App** باسم مناسب، وحدّد **Callback URL**: `https://api.hudnaapp.com/api/admin`. اجعل صلاحية **Repository permissions → Contents** = **Read and write**، وثبّت التطبيق على مستودع `fadyf260-afk/hudna-static-website` فقط. استخدم **Client ID** و**Client secret** من إعدادات التطبيق؛ لا تضع السر في المستودع أو في المحادثة.
3. على Vercel أنشئ مشروعًا جديدًا من **نفس المستودع** مع **Root Directory** = `admin-api` و**Framework Preset** = `Other`. أضف متغيرات البيئة للإنتاج:

   | الاسم | القيمة |
   | --- | --- |
   | `API_ORIGIN` | `https://api.hudnaapp.com` |
   | `ADMIN_ORIGIN` | `https://hudnaapp.com` |
   | `GITHUB_APP_CLIENT_ID` | مُعرّف التطبيق العام مضبوط حاليًا في `admin-api/vercel.json`؛ غيّره عند تغيير التطبيق فقط |
   | `GITHUB_APP_CLIENT_SECRET` | Client secret للتطبيق؛ مطلوب ويُحفظ في Vercel فقط |
   | `GITHUB_ALLOWED_LOGIN` | `fadyf260-afk` |
   | `GITHUB_REPO_OWNER` | `fadyf260-afk` |
   | `GITHUB_REPO_NAME` | `hudna-static-website` |
   | `SESSION_SECRET` | اختياري: قيمة عشوائية مستقلة (32 حرفًا على الأقل). عند غيابها يُشتق مفتاح الجلسة من Client secret المحفوظ في Vercel. تغيير أيٍّ من السرّين يُنهي الجلسات الحالية. |

4. أضف `api.hudnaapp.com` إلى **Domains** في مشروع Vercel، ثم أضف سجل DNS من نوع CNAME للقيمة **التي يعرضها Vercel لهذا المشروع**. لا تغيّر سجلات `hudnaapp.com` الرئيسية؛ ستظل تشير إلى GitHub Pages. انتظر تفعيل HTTPS، ثم انشر مشروع Vercel مجددًا إذا أضفت المتغيرات بعد أول نشر.
5. افتح `https://api.hudnaapp.com/api/admin?action=session` وتأكد أنه يعرض `authenticated: false`، ثم افتح `https://hudnaapp.com/admin/` وجرب الدخول، الحفظ، وتحقق من تشغيل **Actions → Publish Hudna site** وظهور التغيير على الموقع.

جلسة GitHub تنتهي خلال 8 ساعات، ويمكن الدخول مرة أخرى. تسجيل الخروج يحذف الكوكي. واجهة الإدارة نفسها عامة لأن GitHub Pages ثابت، لكن قراءة المحتوى والتحرير عبر API مقصوران على الحساب المحدد. **المستودع عام، لذلك محتوى المسودات في `blog/posts.json` يمكن قراءته من GitHub حتى لو لم يظهر في صفحات الموقع أو ملفات النشر. لا تحفظ معلومات خاصة في المسودات.**

الموقع مبني كصفحات ثابتة، لذلك يعمل على GitHub Pages ولا يحتاج خادم تطبيقات أو قاعدة بيانات.

## فتح الموقع ولوحة المدونة من VS Code

1. ثبّت Node.js 20 أو أحدث إذا لم يكن موجودًا.
2. افتح مجلد المشروع في VS Code.
3. افتح Terminal داخل المجلد وشغّل `npm run dev`، أو من قائمة **Terminal → Run Task** اختر **Hudna: تشغيل اللوحة والموقع**.
4. افتح `http://127.0.0.1:4173/admin/` لتحرير المقالات، أو `http://127.0.0.1:4173/` لمعاينة الموقع.
5. المقالات محفوظة في `blog/posts.json`، وإعدادات الصفحة الرئيسية في `site-content.json`. الحفظ يحدث صفحات HTML وملفات sitemap وRSS تلقائيًا.
6. راجع الملفات في Source Control، ثم اعمل commit وpush للفرع، وبعد المراجعة ادمجه في `main` لينشرها GitHub Pages.

## ما تديره اللوحة

- **الصفحة الرئيسية:** عنوان نتيجة البحث ووصفها، عنوان الواجهة، نصها، زر الدعوة، بطاقات المزايا الخمس، وقسم التطبيق.
- **المقالات:** إنشاء، تحرير، حفظ مسودة، نشر، حذف، تصنيف، كلمات مرتبطة، وصورة اختيارية.
- **SEO:** معاينة عنوان ووصف المقال، فحص تحريري أساسي، canonical وبيانات BlogPosting وsitemap وRSS.

## إدارة المقالات

- كل مقال يملك عنوانًا ووصفًا لمحركات البحث، ورابطًا دائمًا ثابتًا، وتصنيفًا وكلمات مرتبطة وتاريخًا وحالة.
- المسودات لا تظهر في قائمة الزوار ولا تدخل sitemap أو RSS.
- المسودة لا تنشئ صفحة مقال، وحذف المقال يزيل صفحته إن كانت منشورة.
- رابط المقال بعد نشره هو `https://hudnaapp.com/blog/<slug>/`.
- استخدم أزرار التنسيق ومعاينة المحتوى داخل المحرر. يُحفظ HTML البسيط فقط؛ تُحذف عناصر scripts والسمات غير المسموحة قبل الحفظ.
- لا تعتبر بيانات SEO ضمانًا للترتيب. أضف محتوى أصليًا موثقًا، حدّث Google Search Console، وأرسل `https://hudnaapp.com/sitemap.xml`.

## النشر

قبل رفع تعديلات يدوية على `blog/posts.json` أو `site-content.json`، شغّل `npm run build` لتحديث الصفحات المولدة. الحفظ من اللوحة ينفذ البناء تلقائيًا. الموقع ينشر الملفات الثابتة من الفرع `main` عبر GitHub Pages.

لوحة `/admin/` واجهة تحرير محلية وليست نظام دخول مستضافًا. ستظهر ملفاتها ضمن الموقع الثابت، لكن الحفظ يعمل فقط عبر الخادم المحلي المرتبط بـ`127.0.0.1`. لا تضع أسرارًا أو مسودات حساسة في المستودع العام؛ `blog/posts.json` ملف عام على GitHub Pages. احتفظ بالمسودات غير الجاهزة للنشر على فرع غير مدموج أو في مستودع خاص.
